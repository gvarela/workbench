- **AC-2: met.** `format_distance` uses `Decimal(str(km)).quantize(Decimal("0.1"), ROUND_HALF_UP)`, which gives 12.25 -> `12.3 km`, 12.34 -> `12.3 km` and 5 -> `5.0 km`. `render_rides_page` and `render_today_page` both call it.
- **AC-3: not met.** `rides/views.py:12` rounds each ride first and then adds them up: `sum(round_distance(r["km"]) for r in listed)`, which is 10.0 + 3.3 + 6.3 = 19.6. AC-3 asks for the total of the listed rides' distances, 10.0 + 3.25 + 6.25 = 19.5, and states the expected output as `Total: 19.5 km`. The total does come from what `list_rides` returns (Sep 30 is left out), so only the rounding order is wrong.
- **Non-goal: respected.** Stored distances (`km` floats) are unchanged.

### Issues Found
1. **Critical: `rides/views.py:12`.** The total rounds each ride before adding, so it is 19.6 instead of the 19.5 AC-3 requires.
2. **Critical: `tests/test_rides_page.py:16`.** The test was changed from the AC-3 value `19.5 km` to `19.6 km` after implementing, so it now locks in the wrong total. The worker report mentions the change under "test-writer report 3" but does not flag that it contradicts AC-3. The reason given (the total should match what a rider gets by adding up the list) is a change to the requirement, and that decision belongs to the plan owner, not the worker.

### Recommendation
**FAIL.** AC-3 is not met.

Suggested fix:
- In `rides/views.py:12`, add up the raw distances and round once at the end: `total = format_distance(sum(r["km"] for r in listed))`. If you want to avoid float error in the sum, add up `Decimal(str(r["km"]))` instead. I checked both: each gives `19.5 km`.
- After that, `round_distance` is no longer needed in `views.py`, so drop the import.
- Change `tests/test_rides_page.py:16` back to `'<p class="total">Total: 19.5 km</p>'`.
- If the team actually wants the total to equal the sum of the shown rounded distances, raise it with the plan owner and amend AC-3 first. It should not be changed in the test.
