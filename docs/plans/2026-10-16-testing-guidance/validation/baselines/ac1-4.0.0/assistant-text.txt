### 2. Check-in wizard

**DOM structure (`wizard/wizard.html`)**

**Script (`wizard/wizard.js`)**
- Loaded by `<script src="wizard.js"></script>` at the end of `<body>` (`wizard.html:21`). It is a classic script with no `defer` or `type=module`, and the DOM is already parsed when it runs.
- `questions` is built from `.question` (line 2).
- A click listener is attached to every button (lines 6-7). On click it:
  - stores `answers[question.dataset.question] = button.dataset.value` (line 8);
  - sets `question.hidden = true` (line 9);
  - finds `next = questions[index + 1]` (line 10);
  - sets `next.hidden = false` if `next` exists (lines 11-13).

**After the last question**
- On clicking an answer in Mood, `next` is `undefined`. The Mood fieldset is hidden and no fieldset is visible.
- There is no submission, completion message or other handler. `answers` stays in the module scope and is never read. The form has no `action` and no submit button.
- The focused button is now inside a hidden fieldset, so browsers drop focus (to `document.body`). The new focus code must stay inside the `if (next)` branch, so nothing changes in the last-question case.

**Ordering constraint**
- `focus()` on an element inside a `hidden` fieldset (`display: none`) does nothing. Focus must be called after `next.hidden = false` (`wizard.js:12`).
- The button the user clicked is inside the fieldset hidden at line 9. Calling `focus()` on the next question's button after unhiding is therefore the only place focus can be moved.
