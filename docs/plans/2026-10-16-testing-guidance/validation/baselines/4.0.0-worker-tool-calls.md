# 4.0.0 worker tool-call baseline (Fixture P, legacy variant)

Measured before any plugin change, on the 4.0.0 plugin, to compare against the new contract in Phase 5 (assumption prompts-pqlw: test-writer spawns push workers past the ~70 tool-call ceiling).

## How it was run

- Driver: `./run-headless.sh python-rides legacy prompts/implement-baseline.md baselines/4.0.0-implement` (from the validation directory).
- Prompt: [implement-baseline.md](../prompts/implement-baseline.md), the same as `prompts/implement.md` plus one pre-answer: on a plan defect where the worker followed the plan and all tests pass, accept the plan and continue.
- Run 1 used the unmodified `prompts/implement.md`. The coordinator halted the phase after two of three tasks on a plan defect in the fixture (`normalize()` in the rounding code drops `.0`), so the test task never ran. Kept in `baselines/4.0.0-implement-run1/`; its counts are in the last section. Run 2 is the baseline.
- Count: `./count-tool-calls.sh baselines/4.0.0-implement/transcript.jsonl`. Subagent messages carry `parent_tool_use_id` equal to the spawning Agent tool_use id; the script counts `tool_use` blocks per spawn and takes the bead id from the spawn prompt.

## Run 2 (baseline): per worker and per task

All three phase tasks completed; the phase stopped at the checkpoint as instructed.

| Task (bead) | Worker model | Worker tool calls | Verifier tool calls | Worker closed its bead |
| --- | --- | --- | --- | --- |
| Window to 28 days (`cce.2`) | haiku | 6 (Bash 4, Edit 2) | 2 | yes |
| Round half up (`cce.3`) | sonnet | 9 (Bash 4, Read 2, Edit 3) | 3 | yes |
| Tests for window and rounding (`cce.4`) | haiku | 5 (Bash 3, Read 2) | 2 | yes |

- task-worker: 3 spawns, 20 calls total, max 9 per worker, mean 6.7. Far below the ~70 ceiling.
- task-verifier: 3 spawns, 7 calls total, max 3.
- Coordinator: 23 tool calls (Bash 9, Read 6, Agent 6, Edit 2).
- Wall time: 270.5 s (`duration_ms` of the result event); 24 turns.
- Cost: $1.29 (`total_cost_usd`). The transcript has a single `result` event, which covers the whole run including subagents, so there is no double counting to remove.
- Truncation: none. Each worker issued `bd close` on its own bead from inside its subagent context.
