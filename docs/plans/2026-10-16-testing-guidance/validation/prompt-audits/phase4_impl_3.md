## Summary

The diff matches the revised spec: the four new inputs, both new-contract checks, the criterion-protection step, the two report sections, the Boundaries rule, the cause label, and the removal of the npm examples are all present, and no separate flag checklist crept back. The highest-impact problem was in the planted-defect procedure. It set `tmp` in one command and used it in later steps, but the verifier's Bash calls do not share shell variables, so the break, the test run, and the cleanup would each have run against an empty path, and nothing removed the copy if a step failed. The procedure is now one Bash call per planted defect with an `EXIT` trap, run from the repository top (the untracked-file copy was relative to the current directory), and it checks that the break actually applied. A dry run in a scratch repository confirmed it: the patch and untracked files reached the copy, the break failed the test on an assertion, the working tree was unchanged, and the copy, patch, and worktree entry were all gone afterwards. Second, the pointer to the preloaded skill told the verifier to apply its "verdict rule". test-quality's verdicts (Rewrite as a proposal) and its majority-of-three rule for judgment-only findings are reviewer rules. A verifier that followed them could turn a protection FAIL into a proposal or a "review these" item, which is the "minor" grading D6 exists to remove. The sentence now limits the verifier to the skill's Part 1 questions and the expected-value item, and says the gate's verdict comes from Boundaries.
