### Decimal rounding behavior (checked by running it)
Current behavior is `round(km, 1)` at `rides/view_model.py:6`, which keeps the input type. Banker's rounding applies to the exact binary value.

| Input | Current `round(km, 1)` output | Naive `Decimal(str(km)).quantize(Decimal('0.1'))` | With `rounding=ROUND_HALF_UP` |
|---|---|---|---|
| `5` (int) | `"5 km"` | `"5.0 km"` (breaks `test_view_model.py:9`) | `"5.0 km"` |
| `10.0` | `"10.0 km"` | `"10.0 km"` | `"10.0 km"` |
| `12.34` | `"12.3 km"` | `"12.3 km"` | `"12.3 km"` |
| `0.25` | `"0.2 km"` | `"0.2 km"` | `"0.3 km"` |
| `2.675` | `"2.7 km"` | `"2.7 km"` | `"2.7 km"` |
| `-0.25` | `"-0.2 km"` | `"-0.2 km"` | `"-0.3 km"` (rounds away from zero) |

- `Decimal.quantize` defaults to the context rounding, `ROUND_HALF_EVEN`, so the `rounding=ROUND_HALF_UP` argument must be passed explicitly. Without it the naive version still gives `0.2` for `0.25`.
- Using `Decimal(str(km))` rather than `Decimal(km)` avoids binary-float artifacts. For example, `2.675` stays a clean `2.675` and rounds up to `2.7`.
- An int input yields `"5.0 km"` under any quantize variant, because the quantized exponent forces one decimal place. To keep `"5 km"` for `5`, the implementation needs a type branch, for example returning `f"{km} km"` when `isinstance(km, int)`. This is a fact about the existing test, not a recommendation.
- Float `10.0` already renders `"10.0 km"` today, so it is unchanged.
- `bool` is a subclass of `int`, but no caller passes it.

- **`list_rides`** (`store.py:7-11`):
  - `cutoff = today - timedelta(days=WINDOW_DAYS - 1)`.
  - The filter is an inclusive range, `cutoff <= r["date"] <= today`.
  - The result is sorted newest first with `sorted(..., key=lambda r: r["date"], reverse=True)`.
  - With `WINDOW_DAYS = 27`, the window is 27 days inclusive. The `- 1` makes the count inclusive, so 28 gives 28 days inclusive.
- **`load_series`** (`store.py:14-21`):
  - It uses a hard-coded `range(4)` of weeks, not `WINDOW_DAYS`.
  - Each week is `end = today - timedelta(days=7 * week)` and `start = end - timedelta(days=6)`.
  - The same inclusive `start <= r["date"] <= end` comparison is used.
  - It does not depend on `WINDOW_DAYS`, so changing the constant doesn't affect it.
- **Import and docstring style:**
  - The module docstring is one line and states the ride dict shape: `date` (`datetime.date`) and `km` (`float`) (`store.py:1`).
  - Imports are `from datetime import timedelta` (`store.py:2`), and the constant is module-level UPPER_CASE (`store.py:4`).
  - Functions have one-line imperative docstrings, such as "Return rides from…" and "Count rides per week…".

- **`rides/view_model.py`:**
  - The module docstring is one line (`view_model.py:1`).
  - The `format_distance` docstring contains the example "e.g. 12.3 km" (`view_model.py:5`).
