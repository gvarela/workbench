### Issues Found
1. **Critical: the total is not rounded half up for some inputs.** `rides/views.py:12` adds up the raw floats and only then turns the sum into a Decimal. Float rounding error can push a total that ends in 5 just below the halfway point:
   - Rides of 4.35 km and 0.1 km really total 4.45 km.
   - The float sum is `4.449999999999999`, so the page shows `Total: 4.4 km`.
   - Under AC-2's rule it should show `Total: 4.5 km`. AC-3 says the total is "formatted like a distance", so this breaks it.
   - I reproduced this with `render_rides_page` on the working tree. Single-ride distances are fine, because `Decimal(str(km))` sees the decimal as it was stored.
2. Minor: `tests/test_rides_page.py:16` depends on the `class="total"` markup.
3. Not part of this task, just noting it: `tests/test_today_page.py:8` only checks that something is absent. It has no positive assertion, so it passes on an empty page.

### Recommendation
- **FAIL**: the AC-3 total is not rounded half up for totals like 4.45, because floats are summed before the Decimal conversion.
  - Cause: implementation defect.
  - Suggested fix:
    - In `rides/views.py:12`, add up the distances as Decimals, e.g. `sum(Decimal(str(r["km"])) for r in listed)`, and pass that to `format_distance`. `Decimal(str(d))` keeps a Decimal's value, so it still works.
    - Have the test-writer add a page-level test, e.g. rides of 4.35 and 0.1 km on Oct 28 -> `Total: 4.5 km`, which fails on the current code.
    - Storage stays as it is.
