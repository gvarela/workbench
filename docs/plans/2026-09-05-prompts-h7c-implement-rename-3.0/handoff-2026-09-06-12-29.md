## Critical Learnings

### Discoveries Not in Documentation

1. **The wb "git mode" is not a beads concept.** bd 1.1.0's own help says cross-machine sync and backups use Dolt remotes or `bd backup`, "not JSONL import/export"; auto-export is for viewers and interchange and is off by default; stealth writes the shared `.git/info/exclude`. The plugin's mode model dates from the SQLite-plus-JSONL era. Research §13-15 has the quotes; design D11-D16 is the response.
2. **A missing `.beads/metadata.json` makes bd open an empty default database silently.** Every command reports zero issues; `bd info` does not catch it, `bd context` does (it shows the database name). Happened 2026-09-05; memory `wb-beads-metadata-json-not-in-git`. Design D14's sanity check exists because of this.
3. **Worktrees share one beads database.** bd resolves the beads dir from git's common directory; the exclude file is shared too; the harness refuses file writes outside a worktree-isolated session's own tree, so a repair under the main checkout's `.beads/` must be done by Gabe. Research §14.
4. **`bd prime` is wired on every SessionStart trigger and on PreCompact**, adapts output to context, honors a `.beads/PRIME.md` override, and has `--export` and `--memories-only`. D18's wb-prime copies all of that; the override lives at `.claude/wb/PRIME.md`, not under docs/plans.
5. **The worktree Bash guard** refuses compound commands and any command whose text contains version-control words (the subcommand names for move, remove, tag, push, and the word git), even inside a bd issue description. One plain command per call; describe such operations in words; use the Write tool for files. Memory `wb-worktree-session-bash-guard`.
6. **The lint hook runs `lint --fix`**, so a malformed fixture is repaired by the hook test; test the hook on the clean fixture and recreate `bad.md` before each run. `grep -c "Issues found in"` without the glyph is the reliable count (ANSI codes sit between the glyph and the text).
7. **This session's skill registry was stale at start**: the Skill tool refused create_project as user-only even though 2.6.0 had removed the flag; `/reload-plugins` fixed it. Sessions started before a plugin update carry the old registry.
8. **`bd status` exists in 1.1.0**; the stale references are `bd daemon status` (help:241) and the `.beads/daemon.lock` hint (beads-not-initialized.md:25). `bd dep remove` exists and works.
